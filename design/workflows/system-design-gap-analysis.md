# 系统设计差距分析 (System Design Gap Analysis)

**分析日期**: 2026-05-09  
**分析目标**: 检查F2、C1、P1系统设计是否与 `connection-relationship.md` 核心哲学对齐  
**参考文档**: [design/core/connection-relationship.md](../core/connection-relationship.md)

---

## 核心哲学要点回顾

从 `connection-relationship.md` 提取的关键设计要求：

### 三大元原则
1. **玩家不是操作者，而是偶然的邻居** - 角色不为玩家表演
2. **存在感 > 互动感** - 角色的自主生活优先于响应玩家
3. **想象来自不完整** - 不是所有互动都成功，不是所有时刻都可见

### 连接状态作为隐藏主轴
- **远距离连接** (F5 DISCONNECTED/DEGRADED): 角色模糊地意识到观察者
- **稳定连接** (F5 CONNECTED): 角色偶尔朝窗边看，但不直视
- **深度共鸣** (Fe4 长期): 角色在窗边停留更久，但仍保持独立性

### 观察关系约束
- 观察者不在物理空间内
- 角色自洽（不看镜头，不面向玩家）
- 视点必须有物理逻辑（侧面、角落、高处、窗边）
- 禁止面对面社交构图
- 禁止字面意义的"传送门框架"

### 视觉层级
1. **慢变化**（最高优先级，低对比度）- 光影、氛围、季节
2. **角色状态变化** - 姿态、位置、活动
3. **偶发事件** - 特殊互动、外出归来
4. **背景装饰** - 静态元素

## F2 角色状态机 (Character State Machine) 差距分析

### 当前状态列表
- Idle, Attentive, Interacting, Talking, Reacting, Performing, Away, Returning

### 🔴 缺失的关键状态

#### 1. **Aware 状态** (模糊意识到观察者)
- **需求来源**: 远距离连接状态 (F5 DISCONNECTED/DEGRADED)
- **行为描述**: 角色在做自己的事时，偶尔有微妙的停顿或朝窗边看的动作，但不直视玩家
- **与现有状态的区别**:
  - 不同于 Idle（完全沉浸在自己的世界）
  - 不同于 Attentive（当前定义不明确，需要澄清）
- **优先级**: 高 - 这是"远距离连接"的核心表现

#### 2. **Busy_BackTurned 状态** (背对玩家忙碌)
- **需求来源**: "存在感 > 互动感" 原则
- **行为描述**: 角色背对窗口，专注于自己的活动（工作、阅读、整理）
- **设计意义**: 强化"角色不为玩家表演"，玩家只能看到背影和环境
- **优先级**: 中 - 增强真实存在感，但不是核心状态

### 🟡 需要澄清的现有状态

#### 3. **Attentive 状态** - 定义模糊
- **当前触发条件**: 鼠标悬停
- **问题**: 文档未明确角色的视线方向
  - ❌ 如果是"看向镜头/玩家" → 违反"不为玩家表演"原则
  - ✅ 如果是"朝窗边看，但不直视" → 符合"稳定连接"状态
- **建议**: 重新定义为 "朝窗边看，停顿片刻，然后继续自己的事"
- **优先级**: 高 - 这是玩家互动的核心反馈

#### 4. **Performing 状态** - 命名冲突
- **问题**: "Performing" 这个词暗示"为观众表演"，与核心哲学冲突
- **建议**: 
  - 如果是"角色自发的活动"（如弹琴、画画） → 重命名为 "Engaged" 或 "Absorbed"
  - 如果是"响应玩家的特殊互动" → 需要确保动画不是"面向玩家"
- **优先级**: 中 - 命名问题，但可能影响实现方向

### 🟢 符合哲学的现有状态
- **Away**: 完美体现"不完整性"和"不可控性"
- **Returning**: 符合"偶发事件"层级
- **Idle**: 符合"存在感 > 互动感"

## C1 角色动画系统 (Character Animation System) 差距分析

### 当前动画列表
- idle_loop, attentive_loop, interact_in/loop, talk_loop, react_listening, return_in

### 🔴 缺失的关键动画

#### 1. **look_toward_window** (朝窗边看)
- **需求来源**: "稳定连接"状态的视觉表现
- **动画描述**: 
  - 角色从当前活动中抬头/转身
  - 视线朝向窗户方向（不是镜头）
  - 停顿2-3秒
  - 回到原活动
- **关键约束**: 
  - ❌ 不能是"看向镜头"
  - ✅ 应该是"看向窗户的某个点"（如窗框、窗外）
- **优先级**: 高 - 这是"连接感"的核心视觉语言

#### 2. **pause_near_window** (在窗边停留)
- **需求来源**: "深度共鸣"状态 (Fe4)
- **动画描述**: 
  - 角色走到窗边
  - 停留5-10秒（可能看向窗外，或只是站着）
  - 离开窗边
- **设计意义**: 长期陪伴后的亲密感表现，但仍保持独立性
- **优先级**: 中 - 后期内容，但需要预留设计空间

#### 3. **back_turned_busy** (背对玩家忙碌)
- **需求来源**: "存在感 > 互动感" 原则
- **动画描述**: 
  - 角色背对窗口
  - 进行日常活动（整理书架、在桌前工作、收拾房间）
  - 偶尔有身体动作，但看不到表情
- **设计意义**: 强化"玩家是观察者，不是中心"
- **优先级**: 中 - 增强真实感，但不是MVP必需

### 🟡 需要验证的现有动画

#### 4. **attentive_loop** - 视线方向未定义
- **问题**: 如果角色在这个动画中"看向玩家" → 违反核心哲学
- **建议**: 确保视线是"朝窗边看"而非"看镜头"
- **优先级**: 高 - 直接影响观察关系

#### 5. **interact_in/loop** - 构图方式未定义
- **问题**: "互动"时角色的朝向和构图
  - ❌ 如果是"面向玩家展示" → 违反"不为玩家表演"
  - ✅ 如果是"在窗边做某事，玩家从侧面观察" → 符合哲学
- **建议**: 明确互动动画的构图约束
- **优先级**: 高 - 影响所有互动内容的设计

### 🔵 视觉层级问题

#### 6. **慢变化动画缺失**
- **需求来源**: 视觉层级 - "慢变化（最高优先级，低对比度）"
- **当前问题**: 所有动画都是"角色动作"，缺少"慢变化"层
- **建议新增**:
  - 光影变化动画（窗外光线移动）
  - 氛围变化动画（灰尘飘动、窗帘微动）
  - 季节变化动画（窗外景色渐变）
- **实现方式**: 可能不在C1系统内，而是在F1背景系统或独立的氛围系统
- **优先级**: 中 - 需要跨系统协调

## P1 主界面 (Main UI) 差距分析

### 当前设计
- 四层系统：frame, background, character, leak content
- Away状态：背景降至20%亮度

### 🔴 缺失的连接状态视觉表现

#### 1. **F5连接质量的视觉映射**
- **需求来源**: F5 Aria接口的连接状态 (DISCONNECTED, DEGRADED, CONNECTED)
- **当前问题**: 
  - 只定义了 Away 状态（角色不在）
  - 未定义"远距离连接"vs"稳定连接"的视觉差异
- **建议新增**:
  - **DISCONNECTED**: 画面模糊/噪点/色彩饱和度降低（如隔着毛玻璃）
  - **DEGRADED**: 轻微模糊/色彩略微褪色（如隔着纱窗）
  - **CONNECTED**: 清晰画面（当前默认状态）
- **设计意义**: 视觉化"连接"这个核心概念，而不仅仅是"在/不在"
- **优先级**: 高 - 这是"连接关系"的直接视觉语言

#### 2. **"屏幕玻璃"效果缺失**
- **需求来源**: F5系统的"screen glass"概念
- **当前问题**: 文档未提及如何表现"隔着屏幕观察"的质感
- **建议实现**:
  - 微妙的屏幕反光效果（根据连接状态强度变化）
  - 轻微的景深效果（强化"隔着介质观察"）
  - 可选：连接不稳定时的轻微画面抖动/撕裂
- **优先级**: 中 - 增强"观察关系"的物理真实感

### 🟡 需要明确的设计细节

#### 3. **Frame层的"窗框"隐喻**
- **问题**: 当前设计有"frame"层，但未明确是否是"窗框"
- **哲学冲突风险**: 
  - ❌ 如果是明显的"传送门框架" → 违反视觉生成规范 Rule 5
  - ✅ 如果是"软件窗口边框"或"极简边框" → 符合设计
- **建议**: 明确frame层的视觉语言，避免"魔法传送门"感
- **优先级**: 中 - 影响整体视觉风格

#### 4. **Leak Content层的触发逻辑**
- **问题**: 文档未说明leak content如何与"连接状态"关联
- **建议**: 
  - 稳定连接时：leak content更频繁/更清晰
  - 远距离连接时：leak content稀少/模糊
  - 断开连接时：无leak content
- **优先级**: 低 - 细节优化，不影响核心体验

## 跨系统协调问题

### 🟠 F2 ↔ C1 ↔ P1 的状态同步

#### 问题1: 状态命名不一致
- F2定义状态（如 Attentive）
- C1定义动画（如 attentive_loop）
- P1需要根据状态调整视觉效果
- **风险**: 三个系统对"Attentive"的理解可能不一致

#### 问题2: 连接状态的传递链
- F5 → F2 → C1 → P1
- **当前缺失**: F5的连接状态如何影响F2的状态转换？
- **建议**: 在F2文档中明确"连接状态"作为状态转换的输入参数

## 优先级总结

### 🔴 高优先级（影响核心体验）
1. **F2**: 新增 Aware 状态
2. **F2**: 澄清 Attentive 状态的视线方向
3. **C1**: 新增 look_toward_window 动画
4. **C1**: 验证 attentive_loop 和 interact_in 的视线/构图
5. **P1**: 实现 F5 连接质量的视觉映射

### 🟡 中优先级（增强体验完整性）
1. **F2**: 新增 Busy_BackTurned 状态
2. **F2**: 重命名 Performing 状态
3. **C1**: 新增 pause_near_window 动画
4. **C1**: 新增 back_turned_busy 动画
5. **P1**: 实现"屏幕玻璃"效果
6. **P1**: 明确 frame 层的视觉语言

### 🟢 低优先级（细节优化）
1. **C1**: 慢变化动画系统（可能需要新系统）
2. **P1**: Leak Content 与连接状态的关联逻辑
