# Scene Content Framework

*Created: 2026-04-24*
*Status: Draft*
*Purpose: 定义场景内容设计的维度、约束和方法论*

---

## Purpose

本框架定义如何设计「透过窗口看到的异世界场景」的**内容**（what to show），而非**风格**（how to show）。

风格由 `visual-style-guide.md` 和 `art-bible.md` 定义；本框架关注的是：
- 窗口里应该看到什么？
- 这个场景在异世界的什么位置？
- 场景如何体现世界观、角色性格、叙事状态？

---

## Core Constraint（所有主题必须遵守）

### 窗口视角约束

```
玩家的桌面（现实世界）
    ↓ 观察方向
┌─────────────────────┐
│   窗口框架（边界）    │  ← 320×320px 的"洞口"
│  ┌───────────────┐  │
│  │ 异世界场景     │  │  ← 玩家看到的是异世界那边
│  │  [角色]       │  │  ← 角色住在异世界
│  │               │  │
│  └───────────────┘  │
└─────────────────────┘
```

**必须遵守的规则**：
1. **窗口不是玩家的房间** — 玩家看到的是异世界那边的场景，不是现实世界
2. **窥视感** — 玩家只能看到异世界的一个小角落，不是全景
3. **角色的生活空间** — 场景是角色日常生活/工作/休息的地方
4. **有限视野** — 320×320px 的小窗口，信息密度有限，需要分层设计

### 场景功能约束

每个场景主题必须支持：
1. **角色待机** — 角色在场景中的日常状态（Idle、Attentive、Reacting）
2. **角色外出** — 场景变暗（20%亮度），角色不在，但场景仍可辨识
3. **泄漏内容叠加** — 文字、光效可以叠加在场景上而不破坏可读性

### 叙事约束

场景必须：
1. **暗示而非展示** — 不直接展示异世界全貌，只展示一角
2. **留白** — 有足够的想象空间，玩家可以脑补窗口外的世界
3. **生活感** — 场景有被使用的痕迹，不是展示用的样板间

## Scene Content Dimensions（场景内容的5个维度）

每个场景主题需要在这5个维度上做出设计决策：

### Dimension 1: 世界观定位（World Setting）

**问题**：这个异世界是什么样的？

**设计要素**：
- **世界类型**：奇幻 / 蒸汽朋克 / 魔导朋克 / 赛博朋克 / 现代异世界 / 童话 / 其他
- **科技水平**：魔法 / 蒸汽机械 / 现代科技 / 混合
- **社会氛围**：和平 / 冒险 / 日常 / 神秘
- **时代感**：古代 / 中世纪 / 近代 / 现代 / 未来

**输出**：世界观标签（如 "魔导朋克 + 和平日常 + 近代科技"）

**示例**：
- 主题A：魔导朋克世界，魔法与机械共存，和平繁荣的城市
- 主题B：温馨奇幻世界，低魔法，田园牧歌，中世纪风格

---

### Dimension 2: 场景地理位置（Geographic Context）

**问题**：窗口开在异世界的什么地方？

**设计要素**：
- **建筑类型**：住宅 / 店铺 / 工作室 / 学校 / 公共建筑 / 户外
- **城市位置**：市中心 / 居民区 / 郊区 / 乡村 / 荒野
- **楼层高度**：地面 / 低层 / 高层 / 塔楼
- **周边环境**：繁华街道 / 安静小巷 / 广场 / 自然景观

**输出**：地理位置描述（如 "市中心广场边的二楼工作室"）

**示例**：
- 主题A：市中心广场旁的魔导工坊，二楼，窗外可见广场和魔导设备
- 主题B：郊区小屋的阁楼书房，窗外是森林和远山

---

### Dimension 3: 场景功能类型（Functional Space）

**问题**：这个空间是用来做什么的？

**设计要素**：
- **主要功能**：居住 / 工作 / 学习 / 经营 / 社交 / 休息
- **空间类型**：卧室 / 书房 / 工作室 / 店铺 / 起居室 / 厨房 / 其他
- **使用频率**：日常高频 / 偶尔使用 / 特殊场合
- **私密程度**：私人空间 / 半公开 / 公共空间

**输出**：功能定义（如 "个人工作室，日常高频使用，半公开空间"）

**示例**：
- 主题A：魔导工匠的工作室，日常制作魔导道具，半公开（客户可进入）
- 主题B：私人书房，日常学习和休息，完全私密

---

### Dimension 4: 场景叙事状态（Narrative State）

**问题**：场景当前的状态如何体现叙事？

**设计要素**：
- **整洁度**：井井有条 / 适度凌乱 / 混乱
- **使用痕迹**：刚使用过 / 日常状态 / 长期未用
- **氛围**：忙碌 / 悠闲 / 紧张 / 温馨 / 冷清
- **时间线索**：早晨 / 午后 / 傍晚 / 夜晚（通过光照暗示）

**输出**：叙事状态描述（如 "刚工作完，桌面有使用痕迹，傍晚光线"）

**示例**：
- 主题A：工作台上有未完成的魔导装置，工具散落，忙碌氛围
- 主题B：书桌整洁，茶杯还冒着热气，悠闲午后

---

### Dimension 5: 角色性格体现（Character Expression）

**问题**：场景如何体现角色的性格特质？

**设计要素**：
- **整理习惯**：整洁 / 随性 / 混乱
- **装饰风格**：实用主义 / 温馨布置 / 个性化 / 极简
- **物品选择**：工具为主 / 装饰品多 / 收藏品 / 植物
- **色彩偏好**：暖色 / 冷色 / 中性 / 混合

**输出**：性格标签 + 场景表现（如 "整洁型 → 工具归位，装饰简洁"）

**示例**：
- 角色A（严谨型）：工具按类别整齐摆放，标签清晰，无多余装饰
- 角色B（温馨型）：桌上有小盆栽，墙上挂着朋友的画，暖色调
- 角色C（随性型）：书籍堆叠，工具随手放，但有自己的"混乱秩序"

## Layered Composition（分层构图策略）

320×320px 的小窗口需要分层设计，确保信息清晰且有深度感。

### 三层结构

```
┌─────────────────────────────┐
│ 前景层（Foreground）          │  Z: 30  角色活动区，细节最多
│   - 角色站立/坐的位置         │
│   - 桌面/地面物品             │
│   - 可交互元素                │
├─────────────────────────────┤
│ 中景层（Midground）           │  Z: 20  场景主体，定义空间
│   - 家具（桌/椅/床/书架）     │
│   - 墙面装饰                  │
│   - 主要光源                  │
├─────────────────────────────┤
│ 远景层（Background）          │  Z: 10  世界观暗示，细节最少
│   - 窗外景色                  │
│   - 远处建筑/天空             │
│   - 环境光                    │
└─────────────────────────────┘
```

### 分层设计原则

1. **前景（50-70%细节密度）**：
   - 角色活动的核心区域
   - 物品可辨识（书、杯子、工具等）
   - 有使用痕迹（翻开的书、半空的杯子）

2. **中景（30-50%细节密度）**：
   - 定义空间类型（通过家具）
   - 体现角色性格（通过布置）
   - 提供视觉锚点（主要光源、大型家具）

3. **远景（10-30%细节密度）**：
   - 暗示世界观（窗外的异世界景色）
   - 提供深度感（模糊的远景）
   - 不抢夺注意力（色彩饱和度降低）

### 视觉权重分配

| 层级 | 细节密度 | 色彩饱和度 | 对比度 | 功能 |
|------|---------|-----------|--------|------|
| 前景 | 高（50-70%） | 高 | 高 | 角色活动区，叙事焦点 |
| 中景 | 中（30-50%） | 中 | 中 | 空间定义，性格体现 |
| 远景 | 低（10-30%） | 低 | 低 | 世界观暗示，深度感 |

## Scene Element Checklist（场景元素检查清单）

每个场景主题设计完成后，检查是否包含：

### 必须有（Mandatory）

- [ ] **角色活动区**：前景有明确的角色站立/坐的位置
- [ ] **空间定义元素**：至少1-2件大型家具定义空间类型
- [ ] **世界观线索**：至少1个元素暗示这是异世界（魔法物品/奇幻建筑/异常现象）
- [ ] **光源**：明确的光照方向（窗外光/灯光/魔法光）
- [ ] **生活痕迹**：至少2-3个"被使用过"的细节

### 应该有（Recommended）

- [ ] **窗外景色**：远景有异世界的天空/建筑/自然景观
- [ ] **性格线索**：2-3个体现角色性格的物品/布置
- [ ] **叙事钩子**：1-2个可以引发好奇的细节（未完成的工作/神秘物品）
- [ ] **色彩层次**：前景暖色/中景中性/远景冷色（或其他有层次的配色）

### 可选有（Optional）

- [ ] **动态元素暗示**：可以后期添加动画的元素（飘动的窗帘/摇曳的烛光）
- [ ] **季节/天气线索**：窗外景色暗示季节或天气
- [ ] **时间线索**：光照角度暗示时间段

## Integration with Other Systems

### 与游戏设计文档的对接

| GDD 系统 | 场景内容需求 |
|---------|-------------|
| **F2 角色状态机** | 场景需支持 Idle/Attentive/Reacting 动画的空间 |
| **C2 外出-归来循环** | 场景需支持"角色不在"状态（变暗但仍可辨识） |
| **Fe2 泄漏内容系统** | 场景需有足够留白供文字/光效叠加 |
| **C5 性格变量系统** | 场景需有可变元素体现不同性格 |
| **C8 社交圈系统** | 场景可暗示角色的社交关系（照片/礼物/信件） |

### 与视觉风格指南的对接

`scene-content-framework.md`（本文档）定义 **WHAT**：
- 场景里有什么物品
- 物品如何摆放
- 空间如何布局

`visual-style-guide.md` 定义 **HOW**：
- 用什么绘画风格表现（线稿+水彩/油画/像素等）
- 色彩方案（暖色调/冷色调/对比色）
- 笔触质感（粗糙/细腻/速写感）

两者结合 → 生成最终的美术资产

## Workflow Integration

```
1. 游戏设计需求（GDD）
   ↓
2. 场景内容设计（本框架）
   - 填写主题模板（5个维度）
   - 设计分层构图
   - 完成元素检查清单
   ↓
3. 视觉风格应用（visual-style-guide.md）
   - 选择绘画风格
   - 定义色彩方案
   - 确定细节密度
   ↓
4. 提示词生成（scene-generation-workflow.md）
   - 内容描述 + 风格描述 → AI 提示词
   - 分层生成策略
   - 迭代优化流程
   ↓
5. 美术资产产出
   - 导出为 PNG（1920×1080 或 320×320）
   - 进入 assets/art/backgrounds/
   ↓
6. 引擎集成（P1 主界面 UI）
   - 加载为 Layer 2 背景层
   - 支持外出态变暗
   - 支持泄漏内容叠加
```
