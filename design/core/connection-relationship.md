## 文档定位

**这是项目的"宪法"文档**，整合并提升所有已确立的设计哲学。

本文档：
- 整合 `game-concept.md` 中的六大设计柱和五大反柱
- 整合各GDD中已确立的设计思路（F5、C2、Fe2、Fe4等）
- 补充深层洞察，深化核心概念
- 作为所有视觉、交互、叙事决策的最高指导原则

**这不是功能设计文档，而是关系定义文档**

> 项目的核心不是UI、系统或动画，而是「玩家与这个存在之间的关系感」

## 1. 核心幻想

> 你没有在「玩」一个游戏——你打开电脑工作，然后意外发现屏幕角落有一扇小窗口。窗口另一端有个小东西在看着你，它来自你不了解的某个地方，有着你不理解的生活。但它选择留在这扇窗口旁边陪着你。
> 
> 你是它世界的神秘观察者，它是你世界的温柔闯入者。两个世界之间只有这一扇小窗，却足以让两个存在彼此改变。

**来源**：`design/gdd/game-concept.md`

### 核心动词

**窥视（Peek）** — 玩家最常做的事是「瞥一眼屏幕角落，看看它在做什么，发生了什么」。

不是操作，不是管理，是带着好奇心的凝视。

### Unique Hook

**像桌宠游戏，但你不是在养它——你们在彼此陪伴。**

## 2. 六大设计柱

**来源**：`design/gdd/game-concept.md`

| # | 柱名 | 定义 | 设计测试 |
|---|------|------|----------|
| 1 | **窥视感** | 玩家永远只能看到异世界的一个小角落，信息是碎片化、暗示性的，而非全景展示 | 若某功能直接展示异世界全貌 → 违反此柱 |
| 2 | **真实存在感** | 角色有自己的生活、朋友圈和情绪，它的世界在玩家看不到的时候也在运转 | 若角色只在玩家互动时才「活着」 → 违反此柱 |
| 3 | **性格即命运** | 角色的随机性格特质决定它对相同事件的不同反应，性格是叙事分支的核心变量 | 若两个不同性格的角色对同一事件反应相同 → 违反此柱 |
| 4 | **陪伴不打扰** | 游戏常驻桌面但不强制注意力，玩家可以专注工作，有趣的事才会轻柔地吸引你 | 若某功能需要玩家停下工作才能触发 → 违反此柱 |
| 5 | **治愈日常** | 即使是「坏事」也以蠢萌的方式呈现，整体基调永远是温暖和善意的 | 若某事件让玩家感到焦虑或压力 → 违反此柱 |
| 6 | **共鸣成长** | 角色的成长不是数值强化，而是通过共同经历逐渐吸收玩家的正向特质，产生性格层面的内在变化 | 若某「成长」表现为数值提升或战斗强化 → 违反此柱 |

### 五大反柱（我们不做的事）

- **不做收集竞争**：不是集卡游戏，角色不是可量化比较的资产
- **不做实时操作**：不需要玩家停下工作来操作战斗或解谜
- **不做负罪感机制**：不存在「放置太久角色会生气/死亡/离开」的惩罚
- **不做全景世界展示**：永远不直接展示异世界的宏观面貌
- **不做数值成长**：角色不变强，只变得更有深度

## 3. 三大元原则

从六大设计柱提炼并升华，统领全项目的最高原则。

### 元原则 1：玩家不是操作者，而是偶然的邻居

**推导自**：设计柱1（窥视感）+ 设计柱2（真实存在感）

玩家是：
- 偶然发现窗口的人
- 异世界的邻居
- 被另一边模糊感知到的存在

而不是：
- UI 使用者
- 主人
- 控制者

### 元原则 2：存在大于互动

**推导自**：设计柱4（陪伴不打扰）+ 核心动词（窥视）

很多时候：
- 灯亮着
- 她在翻书
- 窗外下雨
- 她不在但杯子还在
- 某本书翻到一半

这些本身就已经形成陪伴。

**存在感 > 互动频率**

### 元原则 3：想象力来自缺失（不完整原则）

**推导自**：设计柱1（窥视感）+ 反柱（不做全景世界展示）

不完整贯穿所有维度：
- **不完整空间** → 永远看不到全貌
- **不完整信息** → 不知道完整背景
- **不完整互动** → 不是每次都回应
- **不完整连接** → 窗口偶尔关闭
- **不完整叙事** → 故事只能拼凑
- **不完整时间** → 她的世界不一定同步

## 4. 连接状态：项目的隐藏主轴

**这个项目真正的核心不是"窗口"，而是「连接状态（Connection State）」**

### 为什么AI接入不矛盾？

因为AI不是"功能开关"，而是**"连接增强器"**

**已确立的设计**（来源：`design/gdd/f5-aria-interface.md`）：
- 未配置API时：屏幕玻璃显示，角色被隔在另一侧
- API接通后：玻璃消失，真实交流通道开启
- 降级模式：交互截断，单向反馈，角色通过动作语言表达

### 连接的三个层级

#### 第一层：遥远连接（Distant Connection）

**对应F5状态**：`DISCONNECTED` / `DEGRADED` / `ERROR`

**核心体验**：
- 观察、等待、窥视、猜测
- 陪伴来自"存在"而非互动
- 像：深夜窗户、远方灯火、异世界广播

**已实现的设计**：
- **屏幕玻璃视觉效果**（F5）：角色被隔在另一侧，声音传不过来
- **角色外出**（C2）：空间上的不稳定，她不总是在那里
- **泄漏内容**（Fe2）：信息碎片化，只能猜测她遭遇了什么
- **降级模式的单向反馈**（F5）：角色通过敲玻璃、写字、发呆等动作语言表达

**情绪关键词**：神秘感、留白感

---

#### 第二层：稳定连接（Shared Presence）

**对应F5状态**：`CONNECTED`

**核心体验**：
- 共处、陪伴、工作同桌
- 她能回应、能帮助、能聊天
- 像：隔壁桌一起学习的人、窗户另一边的邻居

**已实现的设计**：
- **玻璃消失**（F5）：真实交流通道开启
- **语音识别 + LLM调用 + TTS**（F5）：可以对话
- **工作辅助指令路由**（F5）：功能性帮助

**关键边界**：
- ✅ 她更容易被叫到
- ✅ 交流更清晰
- ❌ 但她依然有自己的生活（设计柱2：真实存在感）
- ❌ 不是永远围着玩家转
- ❌ 不是AI助理，而是"邻居"

**即时响应 ≠ 永远围着玩家转**

**情绪关键词**：陪伴感、共处感

---

#### 第三层：深度共鸣（Long-term Resonance）

**对应系统**：Fe4（共鸣成长系统）

**核心体验**：
- 她开始记得你
- 形成习惯
- 空间改变
- 共享记忆

**已实现的设计**：
- **性格漂移计算**（Fe4）：像水滴石穿，在数十小时中悄然发生
- **共鸣等级影响认知升级**（Fe4）：等级越高，记忆深度越大
- **觉醒对话**（Fe4）：角色主动提到自己的改变

**情绪关键词**：时间感、共鸣感

---

### 连接增强的世界观化

**技术实现不应该反向定义体验**

**不要说**：
```
Enable AI
API Connected
Connection Status: Active
```

**而是说**：
```
The connection becomes clearer.
The window stabilizes.
The signal grows warmer tonight.
连接变得清晰了。
窗口稳定下来了。
今晚的信号变暖了。
```

**已实现**：F5的连接状态通过"屏幕玻璃"视觉表现，而非UI提示

## 5. 已确立的核心概念

整合各GDD中已确立的设计思路。

### 5.1 双向连接（不是单向观察）

**来源**：`game-concept.md` + `c2-out-return-cycle.md` + `f5-aria-interface.md`

**已确立的设计**：
- "你不是在养它——你们在彼此陪伴"（game-concept.md）
- "它既独立又在意你：它不是永远围着你转，但也不是彻底断开连接"（C2）
- 外出时携带入口，玩家仍可联系（C2设计）
- 降级模式下角色通过动作语言表达（F5设计）

**需要补充的表现**：
- 角色模糊地感知到玩家（不是看镜头）
- 表现：偶尔朝窗边看、在窗边停留、留纸条、对空气说话

**情绪描述方式**（而非技术描述）：
```
She pauses near the window sometimes.
刚刚好像有人……？（不确定感）
```

**不要变成"AI女友感"**：
- ❌ 错误："你在吗？"（太关注玩家）
- ✅ 正确："刚刚好像有人……？"（不确定感）

---

### 5.2 不完整原则（扩展为统领性原则）

**来源**：`fe2-leak-content-system.md` + `c3-fragment-system.md` + 设计柱1（窥视感）

**已确立的设计**：
- **Fe2**："让玩家想知道，而不是告诉玩家发生了什么"
- **C3**：叙事内容是碎片化的最小单元
- **设计柱1**：只能看到一个小角落

**扩展到所有维度**：
- **不完整空间** → 永远看不到全貌（反柱：不做全景世界展示）
- **不完整信息** → 不知道完整背景（Fe2泄漏内容）
- **不完整互动** → 不是每次都回应（见下方边界说明）
- **不完整连接** → 窗口偶尔关闭（C2外出系统）
- **不完整叙事** → 故事只能拼凑（C3碎片系统）
- **不完整时间** → 她的世界不一定同步

**关于"互动不总是成功"的边界**：
- ✅ **情感性互动**：不总是回应（她在忙、她没注意到）
- ✅ **功能性指令（Aria助手）**：需要响应，但用世界观包装
  - 外出时：延迟响应、弱响应、任务后回馈（C2已设计）
  - 在场时：即时响应，但她仍会忙自己的事

---

### 5.3 时间中的改变

**来源**：`fe4-resonance-growth-system.md`

**已确立的设计**：
- "像水滴石穿一样，在数十小时的陪伴中悄然发生"
- 性格惯性与步长限制：单次归来结算产生的性格总位移不得超过 `DRIFT_CAP`
- 共鸣等级影响认知升级：等级越高，F6系统提示词的深度和广度越大

**核心理念**：
- 陪伴感来自时间累积，不是互动次数
- 角色的改变是缓慢、可预测且具有惯性的

**需要补充的视觉表现**：
- 场景元素随时间变化（书读到一半、植物长大、杯子位置）
- 玩家会"记住她"的习惯和变化

---

### 5.4 边缘存在感

**来源**：设计柱4（陪伴不打扰）+ 核心动词（窥视）

**已确立的设计**：
- "常驻桌面但不强制注意力，玩家可以专注工作"
- "瞥一眼屏幕角落，看看它在做什么"
- **30秒循环**（game-concept.md）：角色常驻角落 → 偶尔有小动画/声音/文字泄漏 → 玩家瞥一眼 → 继续工作

**具体标准**：
- 像桌上盆栽、窗外天气、壁炉火焰、咖啡热气
- 低对比、慢变化、不居中
- 余光可感知，不抢夺注意力

**不是**：
- 强反馈、强提示、高频奖励、主动动画、强可读性

**而是**：
- 允许被注意到的存在

## 6. 深层洞察补充

基于设计柱和已有设计的深化理解。

### 6.1 连接的不稳定性

**核心**：如果窗口太清晰、太稳定、太可控，它就会变成软件UI，而不是被偶然发现的异世界裂缝。

**已有体现**：
- ✅ **角色外出**（C2）：空间上的不稳定，她不总是在那里
- ✅ **泄漏内容随机**（Fe2）：信息上的不稳定，你不总能看清
- ✅ **屏幕玻璃效果**（F5）：连接状态的视觉化

**待实现的补充**（优先级：低，后续考虑）：
- 特定情况下的视觉失真、雾气、波纹
- 但不能是"故障UI"（不要glitch/error/cyberpunk干扰风格）
- 应该像：雾气、水波、光线变化、玻璃反光、夜晚模糊

**克制使用原则**：
- 不稳定性是诗意的，不是技术故障
- 保留浪漫感

---

### 6.2 连接带有阻力（但逐渐减少）

**核心**：陪伴感来自等待。

**遥远连接时**：
- 玩家留东西 → 角色一会儿才发现
- 玩家敲窗 → 角色过很久回应或没看到
- 玩家打开通信器 → 只是停顿一下

**已实现**：
- **C2外出系统**：保底+随机触发，不可控
- **F5降级模式**：交互截断，单向反馈
- **Fe2泄漏内容**：最短间隔5分钟

**稳定连接时**：
- 阻力减少，但不消失
- 她更容易被叫到，但不是永远在线
- 延迟变短，但仍有延迟

**关键**：即时响应 ≠ 永远围着玩家转

---

### 6.3 慢变化优先于快动作

**核心**：边缘存在感来自低频动态，而非高频动画。

**视觉层次**（需更新 `art-direction.md`）：

1. **慢变化**（最高优先级，低对比度）
   - 光线变化、翻书、蒸汽、写字、调药、风吹窗帘
   - 实现：缓慢Tween，低饱和度
   - 玩家会在余光里感知它

2. **角色状态变化**（中优先级）
   - 表情、姿态调整、朝窗边看
   - 实现：柔和过渡，不用弹跳

3. **偶发事件**（低频高对比）
   - 归来、带回碎片
   - 实现：短暂高亮，快速回归平静

## 7. 连接关系的四个维度

### 7.1 玩家是谁？

- **异世界的邻居**（不是操作者）
- 偶然发现了这个连接
- 不能控制她，只能观察和微弱互动
- 也被她模糊地感知到
- 连接增强后：更容易靠近她，但不拥有她

### 7.2 角色是谁？

- **窗口另一端的住户**（不是宠物）
- 有自己的生活和优先级（设计柱2：真实存在感）
- 模糊地知道你在那边
- 即使AI接入，她依然会忙、会离开、会做自己的事
- 玩家只是更容易叫到她

### 7.3 窗口是什么？

- **不稳定的连接**（不是UI）
- 偶然形成的空间裂缝/通信装置
- 连接质量会变化：
  - **遥远连接**：屏幕玻璃、模糊、遮挡（F5已实现）
  - **稳定连接**：玻璃消失，但不完全透明
- 有物理感（波纹、光线、反光）

### 7.4 观看/共处是什么？

- **遥远连接时**：观察、等待、窥视
- **稳定连接时**：共处、同桌、邻居
- **时间久了**：记住彼此、形成习惯（Fe4已设计）
- **永远保留一点不可抵达感**

## 8. 最终镜头语言

已收敛，可直接执行。

### 8.1 被截取的生活镜头（Slice Framing）

- 被门框切割、被书架遮挡、被窗框限制
- 半个房间、半个角色、不对称构图
- 像偶然看到的一瞬间，而非为玩家展示

**正确**：
- 半遮挡、门框、景深、斜角、前景虚化、局部空间、非对称构图、留白

**错误**：
- 完整房间、正中心角色、正对镜头、UI式framing、全信息展示

---

### 8.2 玩家视角必须"有位置"

- 不是神视角
- 透过窗户、裂缝、摆件、通信装置
- 镜头本身有物理性

玩家必须"站在某个地方"观察她。

---

### 8.3 不完整空间原则

- 永远不展示完整世界（反柱：不做全景世界展示）
- 只给：远处塔楼、半个街区、一角天空、窗外模糊景象
- 让玩家脑补

**想象力来自缺失**

---

### 8.4 非表演性镜头

- 角色不永远面对玩家
- 她在忙自己的事、偶尔经过窗边、偶尔停顿
- 生活被偶然看见

**角色不是为你表演**：
- 她在忙自己的事
- 会走开
- 会背对你
- 不总回应你

于是玩家会觉得"她真的活着"。

## 9. 画风收敛

已明确，可直接执行。

### 参考方向

**空间与构图**：
- 建筑速写、微缩舞台、剧场剖面、绘本切片、miniature diorama

**情绪与时间感**：
- 深夜窗户、雨天窗景、小津安二郎、吉卜力生活段落、深夜电台

**观看关系**：
- 偷看别人窗户、阁楼裂缝、博物馆箱庭、旧电视广播

### 视觉关键词（最终公式）

```
minimalist editorial illustration
+ architectural sketch
+ miniature diorama
+ voyeuristic framing
+ slice-of-life staging
+ fragmented composition
+ negative space
+ restrained palette
+ soft temporal atmosphere
```

### 场景密度标准

**玩家一眼应该看到**：

1. **一级信息**：角色正在做什么
2. **二级信息**：空间情绪（夜晚、下雨、温暖、孤独）
3. **三级信息**：远处世界碎片

除此之外都应该弱化。

**不要更多**。

## 11. 与其他文档的关系

### 本文档是"元文档"

- **game-concept.md**：定义了六大设计柱和五大反柱，本文档整合并提升
- **各GDD文档**：实现具体系统，本文档提供哲学指导
- **art-direction.md**：定义视觉风格，本文档提供原则约束
- **scene-content-framework.md**：定义场景内容，本文档提供观看关系约束

### 决策优先级

当设计决策出现冲突时：

1. **本文档的元原则** > 具体系统设计
2. **六大设计柱** > 功能实现
3. **情绪体验** > 技术实现

**技术实现不应该反向定义体验**
